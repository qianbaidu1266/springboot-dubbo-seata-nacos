### 最终根因与修复链（4 个坑）
1. **TC 注册 IP 错误**：seata-server conf/application.yml 里 `registry.preferred-networks: 30.240.*`（本机无此网段），TC 误注册到 xray utun4 虚拟网卡 172.18.0.1，客户端连不上 → 改为 `192.168.43.*`（本机真实网卡），备份 /tmp/seata-server-conf-bak/
2. **【最终阻塞点】TC 必须 JDK 9+**：Seata 2.6.0 server 的 GlobalSession.encode 引用 JDK 9+ 协变返回 API `ByteBuffer.clear()Ljava/nio/ByteBuffer;`，跑 JDK 8 直接 `NoSuchMethodError`，TC 吞异常不回包 → 客户端 GlobalBegin RPC timeout 30s。改用 JDK 17（/Library/Java/JavaVirtualMachines/jdk-17.jdk）重启即通。此前"JDK 25 卡死"系缺 -Dloader.path 的误诊。
3. **PropertiesLauncher**：TC 必须 `-Dloader.path=<seata-server>/lib`，否则 NoClassDefFoundError: SpringApplication
4. **grouplist 直连死路（已回滚）**：registry.type=file + service.grouplist.default 在 SB2.2.2+Seata2.6.0 下三种注入全失败（客户端 ConfigurationFactory 静态快照早于 Spring 桥接），最终回到 registry=nacos + vgroupMapping（camelCase 4 条）

## IDEA 编译报 NoSuchFieldError 修复（Project SDK vs Run JRE）
- 现象：IDEA 编译 business 报 `java: java.lang.NoSuchFieldError: JCTree$JCImport does not have member field 'qualid'`
- 根因：IDEA 双 JDK 设置不一致——Run 配置 ALTERNATIVE_JRE_PATH=1.8（workspace.xml）只影响运行；编译走 Project SDK=21（misc.xml project-jdk-name="21"）的 javac，Lombok 1.18.34 注解处理器在 JDK21 javac 上访问 javac 内部字段炸。用户误以为 Language level 设 8 即用 JDK8——错，language level 只控语法，注解处理器仍在 SDK 的 javac 进程跑
- 修复：.idea/misc.xml `project-jdk-name="21"` → `"1.8"`（languageLevel JDK_8 保留）。注意 IDEA 运行中可能用内存态覆盖该文件，若被覆盖需 GUI 改 File>Project Structure>Project>SDK=1.8
- 经验：SB2.2.2 老工程编译+运行全链路 JDK8（与 mvn 命令行一致）；Lombok 1.18.34 适配 JDK≤23，勿用新 JDK 编译

## samples-common 远程拉取问题（Maven reactor 构建姿势）
- 现象：在 samples-business/ 子目录单独 `mvn clean compile` 报 `io.seata:samples-common:1.0.0 was not found in maven.aliyun.com`，本地仓库仅有 *.lastUpdated 失败标记（从未 install）
- 根因：多模块工程在子模块目录单独构建 = 单模块视角，samples-common 不在当前 reactor 内，只能按坐标去远程找 → 必然失败。与 JDK/IDEA 无关
- 正确姿势：必须在根目录（springboot-dubbo-seata-nacos/）跑 reactor：`mvn clean compile -pl samples-business -am`（-am=also make 连带依赖模块）或全量 `mvn clean compile`；IDEA 同理需以根 pom 为 Maven 工程导入，勿单独 open 子模块
- 兜底方案：若坚持子目录构建，可先在根目录 `mvn install -pl samples-common` 装入本地仓库
- 环境备忘：沙箱 shell PATH 无 mvn，位于 /usr/local/apache-maven-3.9.12/bin/mvn；JDK8 在 ~/javatools/jdk8/Contents/Home（1.8.0_504）。编译用 `JAVA_HOME=~/javatools/jdk8/Contents/Home mvn ...`
